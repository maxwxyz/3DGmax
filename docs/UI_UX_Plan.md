# UI/UX review and plan (PLAN §8.30)

Status 2026-10-28. Complements the principles in [UIUX.md](UIUX.md) (those stay valid); this document reviews the
current UI against five personas, compares four restructuring options and sets a staged plan with measurable
acceptance. Screenshots: `programm/doc_img/de/*.png` (generated by `packaging/doc_screenshots.py`).

## 1. Inventory (counted from the running window, 2026-10-28)
| Area | Count | Notes |
|---|---|---|
| Menu commands | 125 | File 37, View 49, Model 20, Tools 5, Window 10, Help 4 |
| Side panels (docks) | 10 | Structure, Saved views, PMI, Measure, Analysis, Comments, Changes, Scan check, Clashes, Assembly – all compete for the left/right dock areas, several are tabbed on top of each other |
| Toolbar | 9 labeled entries + explosion slider | Open, Compare, Fit all, 3 display modes, Graphical PMI, Measure, Section ▾, Explosion |
| Single-key shortcuts | 25 | 1–7 views, F/Z/N/U/P, E/S/W, G/B/X/M/K/H/I/T … |

Concrete problems found in the inventory and screenshots:
1. **View menu is overloaded (49 commands).** It mixes camera (views, zoom, perspective), display (modes, schemes,
   language), PMI display, tolerance zones, general tolerances and 12 section commands. Tolerance zones and general
   tolerances are analysis functions, not "view".
2. **Duplicates and near-duplicates:** "PMI exportieren (CSV)" and "Änderungen exportieren (CSV)" exist under both
   File › Export and Model; "Teil isolieren" next to "Gewählte Teile isolieren"; "Werkzeug beenden" (Esc) as a menu
   entry.
3. **Tools are scattered by history, not by task:** Analysis and stack-up sit in Model, measure/assembly/clash/scan
   in Tools, compare and manual alignment in File, the change list in Window.
4. **Ten panels for one screen:** a newly opened panel hides another one in the same tab stack; there is no notion of
   "the panels that belong to what I am doing now".
5. **Start page says "STEP-Datei öffnen"** although 12 formats load; it offers neither the recent files nor the 12
   examples nor the other starting tasks (compare, scan check) – a first-time user sees one button.
6. **Findability:** 125 commands, no search over commands. Users of other systems look for words they know
   (CATIA "Section", 3DCS "Measure", metrology "Alignment") and cannot find them without browsing menus.
7. **Panels have no common layout:** some start with a hint label, some with inputs, buttons sit above or below
   tables, export is a button in some panels and a menu entry in others.
8. **Empty states are silent** in several panels (empty table without a sentence on what to do), contrary to
   principle 7 of UIUX.md.

## 2. Personas and task walkthroughs
Personas (none of them may be overwhelmed):
- **CATIA designer (expert):** expects tree left, compass-like cube, middle-mouse navigation, context menus on
  everything, short paths for section/measure/compare; dislikes wizards.
- **3DCS user (variation analyst):** thinks in *moves → tolerances → measures → analysis → contributors*, expects
  result tables with Cp/Cpk and % out, exports for reports.
- **Metrology staff:** alignment (3-2-1, best fit), characteristics with balloon numbers, inspection report;
  occasional CAD use, keyboard less important than clear steps.
- **Layperson / student:** needs plain words, examples, "what do I do next", forgiving undo.
- **Team lead / quality (occasional):** opens a file from an e-mail, reads PMI, compares two revisions, prints a PDF.

Walkthroughs on the current UI (clicks counted from the start page, model already on disk):
| Task | Path today | Clicks/keys | Problem |
|---|---|---|---|
| Open and read PMI | Open → file → PMI panel visible | 3 | fine; PMI list right, model center |
| Compare two states | File › Vergleichen … → two files → dialog | 5–6 | not on the start page; change list in another panel; color map toggle inside that panel |
| Check a scan | Tools › Scan gegen Toleranzen prüfen … → file → panel | 4 | needs the model first – the start page does not say so |
| Build a 1D stack-up | Model › Toleranzkette … → pick faces or PMI → window | 4+ | separate window, not a panel; selection rules in a hint text |
| Assemble and wiggle | Tools › Zusammenbau … → pick 2 faces → Verbinden → table → Wiggle | 6+ per connection | powerful but hidden; measures now in a second tab |
| Find "section by selection" | View › Schnitt › Schnitt an Auswahl | 3 | users of CATIA look in Tools/Analysis |

## 3. Alternatives
| | (a) Workspaces / task tabs | (b) Ribbon | (c) Inspector + command palette | (d) Guided wizards |
|---|---|---|---|---|
| Idea | A row "Ansehen · Prüfen · Vergleichen · Tolerieren · Baugruppe · Scan" above the 3D view; each shows only its panels and its toolbar commands | Tabs with large grouped buttons like CATIA 3DEXPERIENCE / Office | One context panel shows properties and actions of the selection; Ctrl/⌘+K searches every command | Step-by-step dialogs for beginners on top of (a) |
| Pros | Matches the personas' mental models; panels stop competing; keeps menus as full reference | Familiar to CATIA/Office users, discoverable | Fast for experts, no layout change, scales with more commands | Lowest entry barrier |
| Cons | Mode switch must never hide navigation; state per workspace | Takes vertical space, much icon work, hard in Qt without a library | Inspector alone does not structure tasks | Slow for experts, much text |
| Effort | medium (panel/toolbar sets, persistence) | high | low (palette), medium (inspector) | medium per wizard |

Progressive disclosure for all options: defaults that work, advanced options folded ("Mehr …"), a simple/expert
switch only if testing shows the need (it doubles the test matrix).

## 4. Recommendation
**(a) workspaces + command palette (part of c) + a task start page**, CATIA shortcuts and menus kept as the complete
reference. Wizards (d) only where testing shows beginners fail (likely scan check and assembly).

Rules that apply in every stage:
- **Panel layout:** header line with purpose (one sentence), inputs, one primary button, result table, export row
  at the bottom. Empty table → one sentence what to do (and a button when there is a direct action).
- **Wording:** verbs for commands ("Vergleichen", "Messgröße anlegen"), nouns for panels; the same word in menu,
  button, manual and palette; units always shown; no internal terms.
- **Icons:** text first (principle 2); icons only next to text, never alone.
- **Keyboard map:** single keys stay as today (CATIA-like); Ctrl/⌘+K palette; Esc ends every tool; F1 manual.

## 5. Staged plan with acceptance
**Stage 1 – findability without changing the layout (small, safe)** – items 1–5 done 2026-10-28 (item 4: wiggle; other toggles follow when touched):
1. Command palette Ctrl/⌘+K: searches all menu commands (German and English text, menu path, shortcut), Enter runs,
   disabled commands shown greyed with the reason; also under Help.
2. Start page with task tiles: open model, compare two states, examples (list), recent files; format list instead of
   "STEP-Datei öffnen".
3. Menu cleanup: remove the duplicate CSV exports from Model; rename "Teil isolieren" to "Teil der gewählten Fläche
   isolieren" (it is not a duplicate: it isolates the part of the picked face, "Gewählte Teile isolieren" the parts
   picked in the tree); "Werkzeug beenden" stays in the menu because the Esc shortcut lives on that action.
4. Toggles show their state: animation switches become play/pause buttons ("▶ Wiggle" → "⏸ Anhalten", user feedback
   2026-10-28); other checkable buttons keep a visible checked look and a label that names the state.
5. **UI scaling as an option, as in ZGmax** (user request 2026-10-28): View › "Größe der Oberfläche" with 90 / 100 /
   115 / 130 / 150 %, stored in the settings, applied as `QT_SCALE_FACTOR` before the QApplication is created (ZGmax:
   `ui_common.ui_scale_setting`, `drawing_viewer.main`), message "takes effect after a restart" with a restart
   button. Check in the 3D view: OCCT objects that are scaled by devicePixelRatio (view cube, color scale, pivot
   cross) and the picking transform (`_wuerfel_unter_maus`) must follow the changed ratio; PMI text size.
- Acceptance: every command reachable by palette in ≤ 3 keystrokes after Ctrl/⌘+K plus the first letters; students
  find "Schnitt an Auswahl", "Vergleichen" and "Toleranzkette" without help in < 30 s each; no test regresses.

**Stage 2 – workspaces:** workspace row with six entries; each defines its panel set, toolbar group and the menu it
highlights; last workspace per user remembered; Tools/Model menus regrouped by workspace (View keeps camera and
display only; tolerance zones move to "Tolerieren").
- Acceptance: at most 3 panels open per workspace by default; compare task in ≤ 4 clicks from the start page;
  CATIA users rate "finds things where expected" ≥ 4/5.

- Done 2026-10-28 (step 2.1): workspace bar (`ui/arbeitsbereiche.py`) with five workspaces (View, Compare & check,
  Measure & analyse, Tolerancing, Assembly – an output workspace was left out: output has no panel, it lives in
  File › Export); panels that need a state (changes, scan check) only with that state; a tool of another workspace
  moves the bar without hiding its panel; a saved window arrangement wins over the workspace at start-up.

- Done 2026-10-28 (step 2.2): the chain, 2D/3D chain and function windows are panels (bottom dock area, tabbed,
  workspace Tolerancing) – `Hauptfenster._als_leiste`; "Schließen"/Esc closes the panel, reopening shows its content;
  the chain panel switches its splitter to side by side when it is much wider than tall.

- Done 2026-10-28 (step 2.3): rotation blends roll and trackball per mouse move (`navigation.roll_anteil`, circle
  with half the smaller window side, blend 80–98 %, smoothstep); no hint circle (user: not shown, always a circle,
  a bit larger). View cube: unlit grey sides (lit they washed out to white in the fixed pipeline), rebuilt when the
  device pixel ratio changes (screen change on macOS shifted image and hit area).
- Done 2026-10-28 (step 2.4): earlier selected faces 0.78 × the highlight colour, the last one full; comparison
  state ("Vergleich: alt → neu") permanently in the status bar.

- **Top bars (user, 2026-10-28) – done the same day:** one row – workspace selector left in the toolbar, overflow » instead of a
  second row; section and explosion (with their sliders) move into a small row at the top of the structure panel;
  structure, PMI and saved views are never hidden by a workspace switch (only tool panels change); during a
  comparison both structures (new/old) are always shown, labelled.
- **Several models in one assembly (user question, later):** today one window holds one model and the assembly
  works within one STEP file; planned "Modell hinzufügen" (insert another file as parts of the current assembly,
  shown in the structure, connectable like the others).

**Stage 2 additions (user feedback 2026-10-28, approved for implementation):**
- **Panel or dialog – one rule:** everything that belongs to the loaded model and is used next to the 3D view is a
  panel (tab in a side area): structure, PMI, views, measure, compare/check, assembly, clashes, tolerance chain, 2D/3D
  chain, function → tolerancing (today several of these are separate windows). Dialogs only for short, finishing
  inputs: open, export, settings, materials, allocation, approval. A panel never closes through a work action
  (e.g. "Scan ausblenden" closed the scan tab) – actions hide or show content, only the × closes the tab.
- Done 2026-10-28: scan check with the comparison mode bar (Vergleich/Soll/Ist/Nebeneinander/Blinken) and the same review walk (status, comment, G/A keys, counter, report and CSV).
- **Compare and check in one workspace:** a scan check is a comparison "target (CAD) ↔ actual (scan)": the same mode
  bar (overlay, side by side with coupled cameras, blink, target only, actual only), the PMI results (ok / not ok /
  at the limit) in the place of the change list with the same review walk (checked / rejected, comment) and the same
  review report.
- **Visible affordances:** drop-down lists with a clear arrow, editable table cells tinted and editable with one
  click – done 2026-10-28 for every table (`ui/tabellen.py`, delegate tints cells with ItemIsEditable); pressed
  toggle buttons styled (QPushButton:checked); mouse wheel over number fields/lists scrolls instead of changing
  values (`ui/radsperre.py`); chain panel: Add/Chain menus, buttons do not scroll away.
- **Smooth side-panel resizing – analysed and fixed 2026-10-28:** measured per step (resizeDocks + events, FTC-10):
  median 5 ms, but 90th percentile 1088 ms – the preview thread of the saved views ran exact HLR, which holds the GIL
  (about 1 s per view under load). Previews now use the polygonal HLR (`zeichnung.projiziere(schnell=True)`,
  0.03 s): 90th percentile 13 ms. Original item:
  **Smooth side-panel resizing (user report 2026-10-28, still slow and jerky):** the 3D view already batches
  `MustBeResized` (at most every 250 ms, otherwise after the drag) – so the cost is elsewhere. Analysis first, then fix:
  1. Measure per resize step on the Mac and on Windows: time in Qt layout of the dock contents, in Python handlers
     (resize/paint events, table `resizeColumnsToContents`, word-wrapped labels with height-for-width, splitters
     inside docks), and in OCCT (buffer re-creation, redraw); test with an empty model, a large model and with every
     dock open/closed to isolate the culprit.
  2. Likely fixes depending on the result: freeze the 3D view during the drag (show the last frame as an image and
     resize the GL surface once at the end), no content re-layout of hidden tabs, fixed or interactive column widths
     instead of fitting to contents on every resize, cache height-for-width of long hint texts, avoid nested
     splitters in docks.
  3. Acceptance: dragging a side panel follows the mouse at ≥ 30 fps with the NIST FTC-10 model loaded (Mac and
     Windows, normal and mixed DPI); an on-screen test measures the frame time of a scripted drag.
- **Comparison state always visible (user, 2026-10-28):** "Vergleich beenden" closes the "Änderungen" tab (done);
  without a comparison the tab cannot be opened empty – the View menu entry is disabled and the panel says "no
  comparison active" with a button "Zwei Stände vergleichen …" instead of a dead "Prüfen starten". In the comparison
  the tree and the status bar show which two states are loaded (old/new file names, both trees side by side), so it is
  clear whether both models are there.
- **Multi-selection order (user, 2026-10-28):** with several selected faces/elements the earlier ones are shown
  slightly darker than the last selected one (same hue, only a little darker), so the last selection – which e.g.
  decides the reference face of a measure or the end of a chain – is recognisable.
- Done 2026-10-28: examples review – new examples measure, analysis (draft), characteristics with balloons, 2D chain
  (lever template, no model), 3D chain from an assembly measure (19 examples, each tested); scan side by side.
- **Examples for the main functions (user, 2026-10-28):** after the UI stage 2 rebuild, check that every main
  function has an example under File › Examples (and on the start page) that shows it working and explains in one
  line what to look at: compare (geometry, PMI, assembly), scan check, tolerance chain 1D/2D/3D and from an assembly
  measure, function → tolerancing, assembly connections/wiggle and variation, clashes, zones, drawing/section,
  JT/QIF/PRC import. Missing ones get one; examples that open into an empty tab (e.g. "Zusammenbau und Wiggle" shows
  no measures – that is the variation example) say so in their text or open the right tab.
- **CATIA navigation – roll ring and rounded arcball (user, 2026-10-28):** the pure roll area moves further out
  (narrow band near the window edge instead of everything outside 0.45 · min(w, h)); the decision is no longer fixed
  at the press – it follows the cursor while the buttons are held: in the band pure roll about the view axis, moving
  inwards blends continuously into the normal trackball like FreeCAD's "Rounded Arcball" (sphere inside, hyperbolic
  sheet outside, so the rotation axis tilts smoothly towards the view axis – no jump at the border). A faint circle
  shows the roll band while orbiting. Acceptance: on-screen test – a drag from the centre outwards and back rotates
  without a jump, a drag along the band rolls by the swept angle, a drag in the centre orbits as today.

**Stage 3 – inspector and guidance:** context inspector for the selection (face/part/PMI: properties and actions),
guided flows for scan check and assembly variation, unified panel layout everywhere – done 2026-10-28, accepted by
the user on screen the same day (local build of `d97e01c`):
- Inspector panel (`ui/inspektor.py`, in every workspace, tabbed with "Ansichten"): title, property table and the
  actions that fit the selection (zoom, edit, chain, section …) as buttons that follow the action state.
- Guided flows (`ui/fuehrung.py`, Help › Guided and start page): "Scan prüfen" (5 steps) and "Spalt messen" (6 steps);
  each step ticks itself from the app state, one primary button executes it, back/next for free navigation.
- Unified panels: every result table shows a sentence what to do while it is empty (`tabellen.leer_hinweis`), each
  tool panel has one highlighted primary button (Verbinden, Messgröße aus Auswahl, Prüfen, Berechnen, guided step).
  Order checked for every tool panel: purpose sentence on top (`panel_aufbau.zweck_zeile`; added to Messen, Analyse,
  Kommentare, Kollision, Scanprüfung, Änderungen – Zusammenbau tabs, Funktion, 2D/3D chain, guided flows already had
  one), inputs, primary button, result table, secondary commands and export at the bottom (assembly tab
  "Messgrößen": remove / as 3D chain / PDF moved to a bottom row). The chain windows get their table layout and the
  whole UI one control height from the readability/consistency work. Acceptance test with users (≥ 80 %) not run.
- Acceptance: first-use success ≥ 80 % for laypeople on "check a scan" and "measure a gap" with the example data.
- Readable tables (user report 2026-10-28, stack-up windows): `tabellen.spalten_anpassen` sizes every column from
  header, text (capped at ~48 characters, the rest elided with the full text in the tooltip) and the cell widgets'
  size hint – `ResizeToContents` alone measures only item text, so combo boxes and spin boxes were squashed. Rows as
  high as the tallest cell widget, text on one line, numbers and number fields right-aligned, per-pixel horizontal
  scrolling, columns dragged by hand kept. Used in the 1D chain (links, results, scenarios, materials), the 2D segment
  table and the 3D component editor; test `test_gui.py::test_kettentabellen_lesbar`. Checked on screen at 90/100/150 %
  and as a wide, low bottom panel. Other panels can adopt the helper the same way.
- One control height everywhere (user reports 2026-10-28: "alles ist unterschiedlich groß … überall im gesamten
  UI"): `thema.bedien_hoehe()` = font height (≥ 16 px icon) + 2 × 4 px padding + 2 × 1 px border, applied in the
  stylesheet as min/max height to QPushButton, QToolButton, QComboBox, QAbstractSpinBox and QLineEdit; spin boxes
  styled like combo boxes (own arrows), tool buttons framed like push buttons outside the toolbar, menu arrows
  (InstantPopup, MenuButtonPopup, push button menus) one SVG arrow, inner line edits of combos/spin boxes unstyled,
  icon-only buttons square (`thema.nur_symbol`), theme-coloured play/pause icons (`thema.symbol`). A proxy style
  centres form labels on their field (Qt top-aligns them in a row of at most 7/4 text height). Logical pixels, so
  90–150 % interface size scales it. Exceptions: tab bar scroll buttons. Check: `werkzeuge/hoehen.py` and
  `test_gui.py::test_bedienelemente_gleich_hoch` (main window, all docks and dialogs). Chain windows: requirement and
  thermal rows wrap (flow layout) so the panel still shrinks; 3D editor keeps its 18 fields (new fields per selection
  lay over the old ones until Qt deleted them).

## 6. Usability test protocol (local)
- Participants: 2 CATIA designers, 1 3DCS user, 1 metrology staff, 2 students; 30 min each, think aloud.
- Tasks with the example data (File › Examples): (1) find the position tolerance of datum A and its faces,
  (2) compare the two CTC-01 states and name the changed PMI, (3) put a section through the selected hole,
  (4) check the scan and name the worst characteristic, (5) find the main contributor of the head flushness in the
  assembly variation example.
- Measure: time per task, clicks, errors/restarts, unaided success, SUS questionnaire at the end.
- Before and after each stage; results and changes recorded in this document.
